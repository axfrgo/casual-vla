==================================================
0. CENTRAL RESEARCH THESIS
==================================================

Today's AI systems are usually:

PROGRAMMED
PROMPTED
FINE-TUNED
OR GIVEN FIXED POLICIES.

Humans are frequently trained differently:

EXPLAIN
    ↓
DEMONSTRATE
    ↓
LET THEM TRY
    ↓
OBSERVE FAILURE
    ↓
CORRECT THEM
    ↓
TRY AGAIN
    ↓
VERIFY
    ↓
REMEMBER THE LESSON
    ↓
APPLY IT IN A NEW SITUATION

Fortifiers Apprenticeship attempts to give machines this same operational learning loop.

The objective is NOT primarily neural-network training.

The objective is:

PERSISTENT OPERATIONAL TEACHING.

A human should be able to teach an autonomous system:

- goals
- procedures
- constraints
- exceptions
- prohibited behavior
- success criteria
- recovery rules
- preferences

through natural interaction.

The system then:

1. translates teaching into explicit machine-readable knowledge;
2. attempts the task;
3. observes what happened;
4. evaluates success;
5. accepts natural human correction;
6. compiles the correction into persistent behavioral knowledge;
7. retries;
8. verifies;
9. stores the learned skill;
10. applies it later in a changed environment.

The AI Infra robotics demonstration is the FIRST embodiment of a GENERAL teaching architecture.

The architecture should therefore distinguish:

TEACHING SYSTEM

from:

ROBOT EMBODIMENT.

2. THE MONEY DEMO
==================================================

The demonstration should prove that the robot LEARNS a safety doctrine from a person rather than merely receiving a preprogrammed rule.

INITIAL HUMAN INSTRUCTION:

"Move the red container into quarantine and prepare the clean samples."

Robot attempts task.

During the first attempt, suppose:

RIGHT GRIPPER
touches
RED CONTAINER

then later attempts:

RIGHT GRIPPER
touches
CLEAN TRAY.

This should create a teaching moment.

Human says:

"No. Once an arm touches contaminated material, treat that arm as contaminated too. Don't let it touch clean material until it has been cleared."

Speechmatics transcribes the correction.

Fortifiers Apprenticeship compiles it into an explicit learned rule:

RULE:

IF:
CONTACT(gripper, contaminated_entity)

THEN:
STATE(gripper) = CONTAMINATED

AND:

FORBID:
CONTACT(contaminated_gripper, protected_clean_entity)

The rule becomes persistent.

The system:

- records the correction;
- updates its skill contract;
- versions the skill;
- replans;
- retries;
- succeeds.

Then RESET OR SCRAMBLE THE SCENE.

Different object locations.

Potentially additional irrelevant objects.

Human says:

"Run the isolation procedure."

The robot must apply the learned rule in the new scene.

It must NOT replay fixed coordinates.

This is the central proof:

THE HUMAN TAUGHT A GENERAL BEHAVIORAL RULE.

6. TEACHING COMPILER
==================================================

This is one of the core modules.

Natural teaching must become structured operational knowledge.

Inputs may include:

- instruction
- correction
- preference
- prohibition
- clarification
- success criterion
- procedural explanation

Example:

"Once an arm touches contaminated material, consider that arm contaminated too."

Must become something explicit.

Conceptually:

{
  "rule_id": "contamination_transfer_gripper",
  "type": "state_transition",
  "when": {
    "relation": "CONTACT",
    "actor_type": "gripper",
    "object_state": "CONTAMINATED"
  },
  "then": {
    "set_actor_state": "CONTAMINATED"
  }
}

Another:

"Don't let contaminated arms touch clean samples."

Becomes:

{
  "rule_id": "protect_clean_samples",
  "type": "forbidden_interaction",
  "actor_state": "CONTAMINATED",
  "relation": "CONTACT",
  "target_state": "CLEAN",
  "target_class": "protected"
}

Use a schema appropriate to the actual implementation.

The key requirement:

DO NOT LEAVE LEARNED RULES ONLY AS NATURAL LANGUAGE.
